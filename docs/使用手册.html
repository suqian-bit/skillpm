快速上手

skillpm 把 AI Skill 一键装到你用的各个 Agent（WorkBuddy、Claude Code、Codex、Cursor……），并跟着仓库更新。 下面按顺序走一遍：装工具 → 第一次配置 → 看状态 → 更新 → 卸载。每一步的截图都是真实运行的输出。

1. 装工具（只做一次）

Mac / Linux 在终端里粘贴：

git clone https://github.com/suqian-bit/skillpm.git ~/.skillpm-src 2>/dev/null; ~/.skillpm-src/scripts/install.sh

Windows 在 PowerShell 里粘贴：

if (-not (Test-Path $env:USERPROFILE\.skillpm-src)) { git clone https://github.com/suqian-bit/skillpm.git $env:USERPROFILE\.skillpm-src }; Set-ExecutionPolicy -Scope Process Bypass -Force; & "$env:USERPROFILE\.skillpm-src\scripts\install.ps1"

装完敲 skillpm -v 能看到版本号就行；提示找不到命令的话，新开一个终端。

2. 第一次配置 + 装 Skill

skillpm install

第一次会依次问四件事，只有第一个要填，后面三个直接回车就行：

问什么 怎么答
仓库地址 必填：你们团队放 Skill 的 git 仓库地址，找维护的人要；仓库怎么准备见接入自己的仓库
仓库名 回车
装到哪几个 Agent 回车＝本机找到的全装；只要某几个就填序号，比如 1,3
装哪些 Skill 回车＝全装；只要某几个就填序号，比如 5,7,8 或 2-4

填的仓库地址会当场试拉一次，拉不到会说原因、让你重填。以后再跑 skillpm install 就不问仓库了，只问装到哪、装哪些。

3. 看装了什么

skillpm status

每个 Agent 下装了哪些 Skill、什么版本、是不是最新、有没有被人改过：

4. 更新

skillpm update

它会先列出哪些有新版本，回车确认后更新，再把每个 Skill 改了什么念给你，旧版自动备份：

只想看看有没有新版本、先不动：skillpm check

更新工具本身（不是 Skill）：skillpm self-update。有新版本时会念更新日志，手册有更新也会提醒你：

5. 卸载

删 Skill：不写名字会列出来让你挑，确认后才删：

skillpm uninstall

删 skillpm 工具本身：已经装进 Agent 的 Skill 不受影响；要全清干净就先删 Skill 再删工具。 不记得命令就敲 skillpm -h，最后一行「卸载工具本身」给的就是你这台电脑上能直接复制的命令。

Mac / Linux：

~/.skillpm-src/scripts/uninstall.sh

Windows（cmd、PowerShell 都能直接跑，不用改执行策略）：

~\.skillpm-src\scripts\uninstall.cmd

Windows 上别跑 uninstall.sh：Windows 不认 .sh，只会用记事本之类的程序把脚本打开，什么都没卸。

6. 忘了命令

skillpm -h          # 所有命令，按日常 / 配置 / 维护分好组
skillpm docs        # 在浏览器里打开这份手册

任何命令后面加 -h 看它的全部参数；写错了会猜你想写什么，并列出常用写法。

常用命令速查

我想 命令
装 / 补装 Skill skillpm install
全装，不问装哪些 skillpm install --all
只装某几个 skillpm install code-review pdf-tools
装到当前项目（只对这个仓库生效） skillpm install -p
看装了什么 skillpm status
更新 / 不问直接更新 skillpm update / skillpm update --yes
删某个 Skill skillpm uninstall code-review
加一个别的仓库 skillpm repo add <名字> <地址>
装要口令的 Skill（如某个工具的写权限） skillpm install <名字>，在终端里手敲口令（找管理员要）
更新工具本身 skillpm self-update

必须知道的 3 件事

  1. 别人的东西不会被覆盖。 你本地改过的、或者不是本工具装的 Skill，安装和更新都会跳过并告诉你；确实要覆盖加 --force（会先备份）。
  2. 更新前自动备份。 旧版在 ~/.skillpm/backup/<Skill名>/<版本>-<时间>/，想退回直接拷回去。
  3. 多个仓库有同名 Skill： 换来源只在你自己 install 时发生，而且会先问你；update 永远只跟着装的时候那个仓库。

出问题了

现象 先这样
说有冲突、跳过了 你本地改过那个 Skill，或者它不是本工具装的。skillpm status 看是哪个；确认不要本地改动就加 --force
仓库拉不下来 报错会说原因（要登录、找不到、连不上、端口不对、被代理截走……），照提示改
找不到 skillpm 命令 新开一个终端；还不行就重跑第 1 步的安装命令
Agent 里看不到新装的 Skill 重启一下那个 Agent；skillpm status 确认装到的目录对不对
其他问题、建议 填到GitHub Issues

一、速查表

命令 干什么
skillpm install 装 Skill，第一次会引导你配好
skillpm check 只看有没有新版本，什么都不动
skillpm update 检查并更新，打出每个改了什么
skillpm status 每个宿主装了哪些、什么版本、有没有被改过
skillpm ignore <名字> 这个 Skill 不想装，不再提示安装它（--undo 恢复）
skillpm install <名字> 点名装要口令的 Skill（见 2.3）
skillpm publish 维护仓库的人发版：要口令的加密进仓库（见《接入自己的 Skill 仓库》）
skillpm uninstall 删 Skill
skillpm repo add\|list\|remove 管 Skill 仓库（可配多个；别的团队配自己的）
skillpm manifest --check 检查自己的 Skill 仓库合不合格（manifest.json 可选）
skillpm host add\|list\|remove 管宿主（Agent）目录
skillpm sync 重新生成各宿主下的 AGENTS.md 索引
skillpm docs 在浏览器里打开图文使用手册（--path 只打出文件位置）
skillpm self-update 更新工具自己
scripts/install.sh / .ps1 装／更新工具本身
scripts/uninstall.sh / .cmd 删工具本身（Mac/Linux 用 .sh，Windows 用 .cmd）

全局参数（跟在 skillpm 后面，不属于任何子命令）：

参数 说明
-v / -V / --version 看版本号
-h / --help / -help 看帮助。单横线的 -help、-version 也认
skillpm <命令> -h 看这条命令自己的全部参数

参数打错不会只丢一句 unrecognized arguments，会给猜测：

$ skillpm install --hots workbuddy
✗ 没有 --hots 这个参数
  是不是想写 --hosts  或  --host？
  看全部用法：skillpm <命令> -h

二、装 Skill：skillpm install

2.1 全部参数

参数 干什么
SKILL... 要装的 Skill 名，空格分开写多个
--only SKILL... 同上，写不写 --only 都一样
--all 全装，跳过「装哪几个」的询问
--repo 名字 只装这个仓库里的
-a 宿主 / --agent 宿主 只装到这一个宿主
--hosts 宿主... 装到这几个宿主，跳过询问
-d 目录 / --dir 目录 装到指定目录，完全不走宿主探测
-g / --global 装到用户级（默认行为，写不写都一样）
-p / --project 只装到当前项目（仅编程类 Agent）
--force 有冲突也覆盖（覆盖前会先完整备份）
--no-index 不生成 AGENTS.md 索引
--reconfigure 重新走一遍首次引导（换仓库、换令牌时用）

2.1.1 交互选择时怎么填

不带参数跑 skillpm install 会弹选择框（装哪些 Skill、装到哪些宿主）。每个框都是同一套填法：

填什么 意思
直接回车 只选带 * 号的那几个；提示里写明是几个
a / all / * / 全部 列表里全部
1,3,5 / 1 3 5 / 2-4 / 1,3-5 只要这几个
目录路径 只在选宿主时：列表里没有的，直接填 skills 目录，可和序号混填：1,3 ~/.foo/skills
0 一个都不要

skillpm uninstall 的选择框不认 a，只能填序号——删东西不给一键全选。

2.2 穷举各种装法

最常用的三条

skillpm install                     # 问你装到哪、装哪几个
skillpm install --all               # 全装，只问装到哪
skillpm install code-review       # 只装这一个

点名装几个

skillpm install code-review pdf-tools      # 直接写名字
skillpm install --only code-review pdf-tools   # 等价写法

指定从哪个仓库装（配了多个仓库时）

skillpm install --repo 我的库                  # 这个仓库里的全部
skillpm install 我的库:some-skill              # 仓库名:Skill名，点名一个
skillpm install team://我的库/some-skill       # 同上，另一种写法

同名 Skill 出现在多个仓库时，列表里默认是先配的那个；加仓库前缀就能点名要哪个。 已经装了别的仓库的同名 Skill，会先问你要不要换，默认不换；--force 直接换。 完整规则见「六、管仓库」里的「多个仓库、同名 Skill」。

指定装到哪

skillpm install -a workbuddy                        # 只装到 WorkBuddy
skillpm install --hosts workbuddy claude-code       # 装到这两个，不问
skillpm install -d ./my-skills                      # 装到指定目录

⚠️ --hosts 会一路吃到下一个选项为止，Skill 名要写在它前面： skillpm install code-review --hosts workbuddy ✅ skillpm install --hosts workbuddy code-review ❌（code-review 被当成宿主名）

强制覆盖：只接管某一个

目标目录里已经有一份、但不是本工具装的时候，它会跳过并提示。想让它接管：

skillpm install --force --only doc-writer   # 只动这一个
skillpm install --force                                      # 上面列出的全部接管

覆盖前会把原来那份完整备份到 ~/.skillpm/backup/<Skill名>/<版本>-<时间戳>/， 包括工具不认识的文件。加 --only 就只动点名的那个，别的一个不碰。

项目级安装（只有编程类 Agent 支持）

cd ~/work/my-project
skillpm install -p                  # 装到项目里的 .claude/skills，只对这个项目生效

在家目录里用 -p 会被拦下来——~/.claude/skills 本来就是用户级目录， -p 装到的是同一个地方，没有意义。

重新配置

skillpm install --reconfigure       # 重走首次引导：换仓库地址、换令牌

2.3 要口令才能装的 Skill

仓库维护者可以让某些 Skill 要口令才能装（比如权限高的、只给部分人用的），也可以把几个 Skill 设成互斥（同一宿主只装一个，比如同一个工具的只读 / 读写 / 管理三个版本）。 怎么设见《接入自己的 Skill 仓库》的「要口令的 Skill」。装的人这边：

$ skillpm install                       # 列表里没有要口令的，默认装不要口令的那个
  db-tool 组里还有要口令的：db-tool-write、db-tool-admin；要换成它们：skillpm install db-tool-write

$ skillpm install db-tool-write    # 这时才问口令
安装 db-tool-write 需要口令（write 组，找管理员要），输入时不显示：********
✓ 口令正确：db-tool-write
  WorkBuddy：db-tool 组只保留一个，db-tool-read 已换成 db-tool-write

  • 口令只能在终端里手敲，输入不显示，也不支持写在命令行参数里（会进历史记录）。 让 AI 替你跑时，它没有终端可输，会停下来让你自己去终端里运行——口令不要发给 AI。

  • 同一口令组共用一个口令：输对一次记在本机（~/.skillpm/keys.json，权限 600），同组别的 Skill、以后的 update 都不用再输。

  • 一个 Skill 可以配几个口令组，提示里会写「write 或 admin 组的都行」，输哪个都能装；本机记过其中任何一个就不再问。
  • 输错 3 次就不装，原来装的不动。口令被更换后，update 跳过这一项、旧版留着能用，提示重新 skillpm install <名字>。

  • 互斥组同一宿主只留一个：装了高的会把低的换掉；降回去（装不要口令的那个）不用口令。 以前一回车全装上的，第一次 update 会提示：输入要保留的那个的口令；直接回车只留不要口令的那个。

  • --all、按仓库装、交互列表、「仓库里有没装」的提示，都不会带上要口令的 Skill，只能点名装。

  • skillpm status 里会写「权限：write」或「口令组：xxx」。

为什么是加密而不是只判断口令：工具装在每个人自己的机器上，改一行判断就绕过了；仓库人人能拉，明文目录拷走就能用。 所以要口令的 Skill 在仓库里只放加密包（sealed/<名字>.pkg），没有口令拿不到内容。 拿到口令的人能把解开的文件再拷给别人——这个管不住；最终兜底还是平台账号本身的权限。

三、看现状：三条各看一层

skillpm repo list    # 配了哪些仓库、各有多少 Skill、本机装了几个

$ skillpm host list

已配置
  WorkBuddy          C:\Users\你\.workbuddy\skills      装了 8 个

四、更新

4.1 skillpm update —— 更新 Skill

参数 干什么
--repo 名字 只更新来自这个仓库的
--yes 不问直接更新
--force 有冲突也覆盖（先备份）

不写 --repo：所有仓库一起查，但每个 Skill 只跟它装的时候的来源仓库比——不弹出来选仓库， 也永远不会被别的仓库的同名 Skill 顶掉。

$ skillpm update

有 2 项可以更新
  weekly-report  2.6.0 → 2.6.1   （WorkBuddy）
  code-review       2.3.1 → 2.3.2   （WorkBuddy）

确认更新？ [Y/n]:

更新成功：2 个 Skill

weekly-report  2.6.0 → 2.6.1   WorkBuddy
  ## 2.6.1 — 2026-09-20
  - 测试报告明细页「每一步的log」列宽从 60 调到 80。
  旧版备份：~/.skillpm/backup/weekly-report/2.6.0-20260920-093026

更新前只预告谁要变，完整日志留到更新成功之后——没装上的东西不该先把日志给你看。

仓库里有、本机没装的 Skill，update 不会自动装，但每次都会提示，直到装上：

仓库里有 1 个 Skill 本机还没装　update 只更新装过的，新加的要自己装
  case-design  1.1.0    WorkBuddy、WorkBuddy-AI 没装
                        接在需求与用例匹配之后，给「缺口」设计新增用例…
  要装：skillpm install case-design
  不想装、也不想再看到这个提示：skillpm ignore case-design
  • skillpm status 最后也会列这一段。

  • 有的 Skill 你就是不打算装，嫌提示烦：skillpm ignore <名字>，之后就不再提示它。 skillpm ignore 不写名字，列出忽略了哪些；skillpm ignore --undo <名字> 恢复提示。

  • 为什么不自动装：按权限分级、只装一个级别的（SKILL.md 里写了 tier，比如 xx-read / xx-write / xx-admin），装了 -write 的人不该被顺手补上 -admin。 同一个 Skill 的其它级别也不算「没装」，不会提示。

  • 只看你从这个仓库装过东西的宿主；配了仓库却一个都没装过的，当你是有意不用。

4.2 skillpm self-update —— 更新工具自己

skillpm self-update        # 在哪个目录跑都行，不用先 cd

别和上面那条搞混：

命令 更新的是
skillpm update Skill 内容（怎么拆用例、怎么出报告……）
skillpm self-update skillpm 工具本身（命令、参数、提示……）

4.3 skillpm sync —— 重建索引

在各宿主目录下重写 AGENTS.md（列出装了哪些、什么版本、干什么用）。不动 Skill 本身。

skillpm sync

install / update 会自动生成，一般不用手动跑。手动跑的场景：手改过 AGENTS.md 想恢复，或装的时候加了 --no-index。

索引写在一对标记之间，标记外面你手写的内容会原样保留。

五、删除（两个，别搞混）

这是最容易搞混的地方，它们删的不是一个东西：

删什么 命令 删完
删 Skill 装到各 Agent 目录里的 Skill skillpm uninstall 工具还在，随时能再装回来
删工具 skillpm 这个命令本身 scripts/uninstall.sh / .cmd 命令没了，已装的 Skill 原地不动 
                   skillpm uninstall              scripts/uninstall.sh --all
                          ↓                                   ↓
  ~/.workbuddy/skills/skillpm-*     ← 删这些      ~/.local/bin/skillpm  ← 删这个
  ~/.claude/skills/skillpm-*                      ~/.skillpm/（配置、记录、缓存、备份）
                                                   ~/.skillpm-src/（源码，要手动删）

要全清干净，先删 Skill 再删工具，见 5.3。

5.1 skillpm uninstall —— 删 Skill

参数 干什么
SKILL... 要删的 Skill 名，可以写多个
--only SKILL... 同上，写不写都行
--all 删掉本工具装的全部
--host 宿主 只动这个宿主（大小写、空格随便写）
--yes 不再确认 
skillpm uninstall                       # 不写名字：列出来让你勾（默认一个都不选）
skillpm uninstall code-review         # 删这一个
skillpm uninstall flow artifacts        # 删多个
skillpm uninstall --all                 # 全删，会先列清单让你确认
skillpm uninstall --all --yes           # 全删，不确认（脚本里用）
skillpm uninstall --host workbuddy --all   # 只清 WorkBuddy 这一个宿主

$ skillpm uninstall --all --yes

要移除这些（只动本工具装的，别人放的不碰）
  weekly-report    WorkBuddy   C:\Users\你\.workbuddy\skills\weekly-report
  code-review         WorkBuddy   C:\Users\你\.workbuddy\skills\code-review
  ...
✓ WorkBuddy  weekly-report 已移除
✓ WorkBuddy  code-review 已移除

它只删自己装的。 你手动拷进去的那份它认不出来，也就删不掉—— 那种情况要么自己删目录，要么先 skillpm install --force --only <名字> 让它接管。

--yes 是「别问我，直接删」。破坏性操作建议先不加，看一眼清单再回车。

5.2 scripts/uninstall.sh / .cmd —— 删工具本身

Mac / Linux

~/.skillpm-src/scripts/uninstall.sh           # 只卸工具，配置和已装的 Skill 都留着
~/.skillpm-src/scripts/uninstall.sh --all     # 连 ~/.skillpm 一起删

Windows（cmd、PowerShell 里都能直接跑，不用改执行策略）

~\.skillpm-src\scripts\uninstall.cmd          # 只卸工具
~\.skillpm-src\scripts\uninstall.cmd -All     # 连 .skillpm 一起删

uninstall.cmd 只是个壳，自己带上执行策略参数去调同目录的 uninstall.ps1；在 cmd 里 ~ 不认，写 %USERPROFILE%\.skillpm-src\scripts\uninstall.cmd。记不住就看 skillpm -h 最后一行，给的是本机的绝对路径。

Windows 上别跑 uninstall.sh：Windows 不认 .sh，只会用关联的程序把脚本打开，什么都没卸。

参数 删什么 不删什么
（不加） 启动器 / pip 包 ~/.skillpm（配置、安装记录、缓存、备份）、已装的 Skill
--all / -All 上面那些 ＋ ~/.skillpm 已装的 Skill、~/.skillpm-src 源码

加 --all / -All 时会明确问你一次（要删掉 ... 吗？[y/N]），这个没有跳过的参数。

它不动已经装到各宿主目录里的 Skill，也不动 PATH里那条目录 （指向一个空目录而已，无害；想清就自己去环境变量里删）。

源码目录要手动删：

rm -rf ~/.skillpm-src                                    # Mac
Remove-Item -Recurse -Force $env:USERPROFILE\.skillpm-src   # Windows

5.3 完整清理（三步，顺序别反）

# Mac / Linux
skillpm uninstall --all --yes
~/.skillpm-src/scripts/uninstall.sh --all
rm -rf ~/.skillpm-src

# Windows
skillpm uninstall --all --yes
~\.skillpm-src\scripts\uninstall.cmd -All
Remove-Item -Recurse -Force $env:USERPROFILE\.skillpm-src

六、管仓库：skillpm repo

别的团队要接自己的 Skill 仓库，看 接入自己的Skill仓库.md，从整理仓库到加进来一步步都有。

skillpm repo                                              # 不写动作＝列出已配的，顺带给常用写法
skillpm repo add 我们团队 http://gitlab.example.com/组/仓库.git        # 地址直接写，http/git@ 自动认
skillpm repo add 我们团队 git@gitlab.example.com:组/仓库.git
skillpm repo add 我们团队 http://gitlab.example.com/组/仓库.git --token <令牌>   # 私有仓库
skillpm repo add 我们团队 http://gitlab.example.com/组/仓库.git --branch dev     # 不是 main 分支
skillpm repo remove 我们团队                               # 只删配置，不动已装的 Skill

repo add 会先试拉一次：拉得到、里面有能装的 Skill 才保存，并告诉你有几个； 拉不到就说清楚是哪种原因（要登录／找不到仓库／连不上／端口不对／SSH 没过／没有这个分支／没有能装的 Skill），不保存。 同名再 add 一次就是改地址、改令牌。

参数 干什么
<名字> <地址> 名字自己起；地址写 http(s)://…/组/仓库(.git) 或 git@主机:组/仓库.git
--token 令牌 私有仓库的访问令牌。屏幕输出和报错里一律打码
--branch 分支 默认 main
--no-check 不试拉，直接记下（离线时配置用）
--http-only 不用 git，下载压缩包（要令牌）
--ssh 地址 / --http 地址 / --path 组/项目 旧写法，照样能用；地址直接写在名字后面更省事
--yes remove 时不再确认

配好之后这些命令都能限定范围：install --repo、check --repo、update --repo。

多个仓库、同名 Skill：规则就两条

同一个 Agent 下，同名的 Skill 只能留一个。可以从多个仓库装，平时名字不会撞；撞了按下面两条走：

① 换来源只发生在你自己 install 的时候，而且一定先问你

情况 结果
不重名 正常装
同一个仓库重装、升级 正常装，不问
已装的 A 来自甲，这次要装乙的 A 停下来问，默认不换：
回 y → 覆盖成乙的，以后跟着乙更新
回 n（或直接回车）→ 跳过，还是甲的
不想被问 skillpm install 乙:A --force（只换这一个）
skillpm install --repo 乙 --force（乙的全换）
脚本、CI 里没法回答 默认不换，退出码 1，提示加 --force 
! WorkBuddy：A 现在装的是「甲」的 1.0.0，这次要换成「乙」的 5.0.0
  同一个 Agent 下同名的只能留一个；换了以后就跟着新仓库更新
  确定换吗？[y/N]

② update 永远不换来源

每个装上的 Skill 都记着「从哪个仓库装的」，update 只拿它跟那个仓库比：

  • 不写 --repo：所有仓库都拉一遍，但 A 只跟甲比、B 只跟乙比，别的仓库里有没有同名的都不影响。 不会弹出来让你选仓库——每个 Skill 该跟哪个仓库，装的时候就定了。

  • 写 --repo 乙：只更新从乙装的那些。

  • 只更新你装过的；仓库里新加的、你没装过的不会自己装上。
  • 来源仓库被 repo remove 了、或者里面没有这个 Skill 了：不更新、说明原因，不拿别的仓库的同名 Skill 顶上。

为什么两条都要：只有 ① 不够。比如从乙装了 A，后来又加了个仓库丙、里面恰好也有 A—— 你没去装丙的 A，① 根本不会触发；是 ② 保证了 update 只认乙。

1.20.1 之前 update 按名字找、先配的仓库优先：从乙装的 A 会被悄悄换成甲的，版本还可能倒退。 1.20.2 之前 install 换来源不问，直接顶掉。现在两处都修了。

六·五、检查自己的仓库：skillpm manifest

仓库要能被安装，只要一条：Skill 放在 skills/<名字>/SKILL.md，开头 frontmatter 里写 name（和目录名一样）和 description；version 可选。 不需要任何配置文件——manifest.json 是可选的：没有就按 skills/ 当场算，有就用它。

skillpm manifest --check            # 只检查：每个 Skill 合不合格；有 manifest.json 的话再查它是不是最新。不合格退出码 1（CI 用）
skillpm manifest                    # 生成 manifest.json（可选；生成了就得每次改完都重新生成）
skillpm manifest ~/code/我们的仓库   # 指定目录
检查项 不满足时
有 skills/ 目录，里面至少一个 SKILL.md 报错
SKILL.md 有 frontmatter，name 和目录名一致 报错
写了 description 提醒
写了 version（顶层或 metadata: 下都行）；不写就按文件内容判断更新 提醒
有 CHANGELOG.md，且有当前版本那一节 提醒
（有 manifest.json 时）它和 skills/ 对得上，没有「文件改了、版本号没动」 报错

不合格的 Skill 装的时候会被跳过并提示原因，同一个仓库里别的 Skill 照常能装。

八、装/更新工具本身的脚本参数

Mac / Linux —— scripts/install.sh

写法 干什么
./scripts/install.sh 自动挑一种能用的装法（默认＝启动器）
./scripts/install.sh --launcher 强制只做启动器（最快，零网络）
./scripts/install.sh --pip 强制用 pip（要能连 PyPI）
PREFIX=/some/bin ./scripts/install.sh 指定装到哪个目录

Windows —— scripts\install.ps1

参数 干什么
-Mode launcher 只做启动器（默认）
-Mode pip 用 pip 装
-Prefix D:\bin 指定装到哪
-Yes 不弹任何询问，PATH 直接加（批量铺开、CI 用）

重复运行就是更新：脚本会先 git pull 再重新链接，所以「装」和「更新」是同一条命令。

⚠️ Windows 上用 & 调用，别用 powershell -File： -File 会另起一个进程，它改的 $env:PATH 传不回你的窗口，装完得重开终端。 & 是在当前会话里跑，装完直接就能敲 skillpm。

变量 干什么
SKILLPM_HOME 换掉 ~/.skillpm（配置、状态、缓存、备份都跟着走）
SKILLPM_REPO bootstrap 脚本从哪个地址克隆工具源码

码 什么意思
0 成功

130 你按了 Ctrl-C（没做完的改动不会留下）

~/.skillpm-src/            工具源码（写死的位置，self-update 去这儿拉）
~/.skillpm/
  ├── config.json           仓库地址、令牌、宿主路径（权限 600）

第一步：仓库长这样

Skill 用的是通用的 Agent Skill 格式，现成的 Skill 直接放进 skills/ 就能装：

你们的仓库/
└── skills/                     ← 固定叫这个名字
    ├── 某个-skill/             ← 一个 Skill 一个目录，目录名就是 Skill 名
    │   ├── SKILL.md            ← 必须有
    │   ├── CHANGELOG.md        ← 建议有
    │   ├── references/         ← 可选：参考资料，SKILL.md 里用到时再读
    │   ├── scripts/            ← 可选：要执行的脚本
    │   └── assets/             ← 可选：模板、图片等素材
    └── 另一个-skill/
        └── SKILL.md

目录里的所有文件都会原样装过去。

SKILL.md 格式

---
name: 某个-skill
description: 一句话说清楚干什么、什么时候该用它（Agent 靠这句决定要不要用）
version: 1.0.0
---

# 某个 Skill

正文：给 Agent 看的操作说明、步骤、注意事项……
字段 要不要写 说明
name 必须 和目录名一模一样
description 必须（不写只提醒） Agent 靠它判断什么时候用这个 Skill，写清「干什么 + 什么时候用」
version 建议 写了：更新时能看到「1.0.0 → 1.1.0」和更新日志。不写也能装：按文件内容判断有没有更新，版本显示成「未标版本-xxxxxxx」

version 放在顶层或 metadata: 下面都认。

CHANGELOG.md 格式（建议）

每次改版本加一节，标题写版本号，最新的在最上面。别人 skillpm update 时会把这中间的几节念给他看：

## 1.0.1 — 2026-09-21
- 修了 xxx

## 1.0.0 — 2026-09-01
- 初版

就这些，不需要别的配置文件。 以后改了 Skill：改一下 version、写一节 CHANGELOG，推上去，别人 skillpm update 就能看到。

照提示把 name 改成和目录名一样，再检一次：

关于 manifest.json：它是可选的。仓库里没有，skillpm 装的时候直接按 skills/ 当场算； 有的话就用它。建议不要提交——提交了就得每次改完都重新生成（skillpm manifest）， 忘了的话别人看到的是旧版本号。有自己发版流程、想在发布时再把一道关的仓库，才值得保留它。

仓库权限：最省事是开匿名读（GitLab → 项目设置 → 可见性 → 公开/内部），这样大家不用配 SSH key、不用令牌。 不方便公开的，见下面「私有仓库」。

可选：要口令的 Skill、互斥的 Skill

有的 Skill 不想人人都能装（权限高、只给部分人），在仓库根目录放一个 skillpm.repo.json：

{
  "locked": {
    "db-tool-write": {"lock": ["write", "admin"], "hint": "找管理员要"},
    "db-tool-admin": {"lock": "admin", "hint": "找管理员要"},
    "some-internal-tool": {"lock": "leads"}
  },
  "exclusive": {
    "db-tool": ["db-tool-read", "db-tool-write", "db-tool-admin"]
  }
}
  • locked：这些 Skill 要口令才能装。lock 是口令组的名字（不是口令本身），同一组共用一个口令（几个工具都写 leads，发一个口令全能装）；hint 是装的时候提示口令找谁要。
  • lock 也可以写几个组：["write", "admin"] 表示这两个组的口令都能装它。有高低的用这个最顺手——拿到 admin 口令的人，write 也能自己装，不用再要一个。
  • exclusive（可选，和口令无关）：几个 Skill 互为替代，同一宿主只装一个，按从低到高排；默认装最低、不要口令的那个。

要口令的 Skill 明文不能进仓库：仓库里只放加密包 sealed/<名字>.pkg。明文放在你自己机器上，发版用：

skillpm publish <明文 Skill 目录> --repo <仓库本地目录>          # 全发；--only a b 只发这几个
  • 配置里列了的加密进 sealed/，其余复制到 skills/，最后重建 manifest.json；只动文件，不替你 git commit。
  • 口令在终端里输（或环境变量 SKILLPM_LOCK_<口令组>）。仓库里已经有这个组的包时，先核对口令，输错了不发，免得发出一批谁都打不开的包；第一次要输两遍。
  • 内容没变的不重新加密（每次加密结果都不一样，重做会让 git 平白多一条改动）。
  • 换口令：--new-password <口令组>，这个组的 Skill 要一起发（不然一部分新口令、一部分旧口令）。换完把新口令发给该给的人；旧口令打不开新版本，他们 update 时会被提示重输。
  • 已经推过明文的，git 历史里还留着：要彻底去掉得改写历史并强制推送，大家要重新拉——这一步想清楚再做。

第三步：每个人把仓库加进来

然后装：

不是 main 分支

和别的仓库有同名的 Skill

同一个 Agent 下同名的只能留一个。两条规则：

  1. 换来源只发生在你自己 install 的时候，而且一定先问你，默认不换；--force 直接换。
  2. update 永远不换来源：每个 Skill 只跟它装的时候的那个仓库比，别的仓库里有没有同名的都不影响。

所以起 Skill 名字时尽量带上团队或业务前缀（比如 ops-巡检），能从根上避免撞名。

2.3.02026-09-23一个 Skill 可以配几个口令组

  • 一个 Skill 可以配几个口令组：skillpm.repo.json 里 "lock": ["write", "admin"]，这两个组的口令都能装它。 有高低的用这个最顺手：拿到 admin 口令的人，write 也能自己装，不用再要一个 write 口令。

  • 装的时候提示「write 或 admin 组的都行」；本机记过其中任何一个组的口令就不再问，输对的口令记在它实际打开的那个组名下。

  • publish 按组分别核对：问 write 组的口令时输成 admin 的，哪怕它也能打开这个包，也拦下来——不然 write 那份会被悄悄换成 admin 的口令。
  • --new-password <组> 换口令时，配了这个组的 Skill 都要一起发。
  • 包格式没变；只写一个组名的配置照旧能用。
2.2.02026-09-23仓库里的 Skill 可以设成要口令才能装；几个 Skill 可以设成互斥（同一宿主只装一个）。

仓库里的 Skill 可以设成要口令才能装；几个 Skill 可以设成互斥（同一宿主只装一个）。

起因：同一个工具分了只读 / 读写 / 管理三个版本，可 install 的列表默认全选，一回车三个全装上，分级起不到管控作用。 哪个 Skill 要口令、用哪个口令组、哪些互斥，都由仓库根目录的 skillpm.repo.json 决定，不写死在工具里。

  • 要口令的 Skill 加密存放：仓库里只放 sealed/<名字>.pkg，装的时候在终端里输口令解开。同一口令组共用一个口令。 口令只能手敲（不显示、不进命令行）；没有终端（AI 替人跑）时直接停下，让人自己去终端运行。输错 3 次不装，原来装的不动。 输对一次记在本机 ~/.skillpm/keys.json（600），同组别的 Skill 和以后的 update 不再问；口令被更换时 update 跳过这一项、旧版留着，提示重新输。

  • 默认不装要口令的：交互列表、--all、按仓库装、「仓库里有没装」的提示都不带它们，只能点名装。

  • 互斥组：同一宿主只留一个，装高的自动换掉低的，降回去不用口令；以前一回车全装上的，第一次 update 输口令选保留哪个，直接回车只留不要口令的那个。
  • status 显示「权限：write」或「口令组：xxx」。

  • 新命令 skillpm publish（维护仓库的人用）：配置里要口令的加密进 sealed/，其余复制到 skills/，重建 manifest。 已有这个组的包时先核对口令，输错不发；内容没变的不重做；--new-password 换口令时组里的 Skill 要一起发。

  • 加密只用标准库：PBKDF2-HMAC-SHA256 派生密钥，HMAC-SHA256 生成密钥流加密并校验，口令不对或包被改过都解不开。 内容用随机密钥加密、随机密钥再用口令加密（信封加密），以后要「每人一个口令、单独撤销某个人」不用改包格式。

  • 为什么要加密而不是只判断口令：工具装在各人机器上，改一行判断就绕过了；仓库人人能拉，明文目录拷走就能用。 拿到口令的人能把解开的文件再转给别人，这个管不住；最终兜底仍是平台账号本身的权限。

2.0.02026-09-21首个公开版本。

首个公开版本。 把放在 git 仓库里的 AI Skill 一键装到本机的各个 Agent，并跟着仓库更新。

和 1.x 的不兼容之处：不再内置默认的 Skill 仓库。 第一次运行 skillpm install 时必须填你们团队的仓库地址； 已经配好的人不受影响。

能做什么

  • 一键装到多个 Agent：认识 52 种常见 Agent 的 Skill 目录（Claude Code、Codex、Cursor、Windsurf、Gemini CLI、 Qoder、Trae、WorkBuddy……），表里没有的按「家目录的隐藏文件夹下有 skills」自动发现，也能手填目录。

  • 跟着仓库更新：skillpm update 列出新版本，确认后更新，并把每个 Skill 的更新日志念给你；旧版自动备份。

  • 不碰别人的东西：本地改过的、不是本工具装的 Skill，安装和更新都跳过并说明；--force 覆盖前先完整备份。

  • 多个仓库：可以同时配多个仓库。同名 Skill 换来源只在你自己 install 时发生、而且会先问你； update 永远只跟着装的时候那个仓库。

  • Skill 仓库几乎零要求：通用 Agent Skill 格式（skills/<名字>/SKILL.md，写好 name、description）就能装； version、CHANGELOG.md、manifest.json 都可选。skillpm manifest --check 自检，适合放 CI。

  • 私有仓库：--token 访问令牌（不进命令行、不落盘到缓存的 git 配置），或者 SSH。

  • 锁版本：skillpm freeze 导出锁文件，别人 install --from 装到完全一样的一套。
  • 项目级安装：-p 只装到当前项目，版本写进锁文件随项目提交。
  • 中文友好：全部提示和报错是中文，写错命令会猜你想写什么并列出常用写法；拉取失败按原因给出下一步。
  • 图文手册随工具发：skillpm docs 在浏览器里打开，快速上手每一步都有真实截图。
  • 零依赖：只用 Python 3.8+ 标准库；Mac / Windows / Linux 通用，安装脚本默认不碰 PyPI。
