## 一、速查表

| 命令 | 干什么 |
|---|---|
| `skillpm install` | 装 Skill，第一次会引导你配好 |
| `skillpm check` | 只看有没有新版本，什么都不动 |
| `skillpm update` | 检查并更新，打出每个改了什么 |
| `skillpm status` | 每个宿主装了哪些、什么版本、有没有被改过 |
| `skillpm uninstall` | **删 Skill** |
| `skillpm repo add\|list\|remove` | 管 Skill 仓库（可配多个；别的团队配自己的） |
| `skillpm manifest --check` | 检查自己的 Skill 仓库合不合格（manifest.json 可选） |
| `skillpm host add\|list\|remove` | 管宿主（Agent）目录 |
| `skillpm freeze` | 导出锁文件，让全组装到完全一样的版本 |
| `skillpm sync` | 重新生成各宿主下的 `AGENTS.md` 索引 |
| `skillpm docs` | 在浏览器里打开图文使用手册（`--path` 只打出文件位置） |
| `skillpm self-update` | 更新工具自己 |
| `scripts/install.sh` / `.ps1` | 装／更新**工具本身** |
| `scripts/uninstall.sh` / `.ps1` | **删工具本身** |

**全局参数**（跟在 `skillpm` 后面，不属于任何子命令）：

| 参数 | 说明 |
|---|---|
| `-v` / `-V` / `--version` | 看版本号 |
| `-h` / `--help` / `-help` | 看帮助。单横线的 `-help`、`-version` 也认 |
| `skillpm <命令> -h` | 看**这条命令**自己的全部参数 |

参数打错不会只丢一句 `unrecognized arguments`，会给猜测：

```
$ skillpm install --hots workbuddy
✗ 没有 --hots 这个参数
  是不是想写 --hosts  或  --host？
  看全部用法：skillpm <命令> -h
```

## 二、装 Skill：`skillpm install`

### 2.1 全部参数

| 参数 | 干什么 |
|---|---|
| `SKILL...` | 要装的 Skill 名，空格分开写多个 |
| `--only SKILL...` | 同上，写不写 `--only` 都一样 |
| `--all` | 全装，跳过「装哪几个」的询问 |
| `--repo 名字` | 只装这个仓库里的 |
| `-a 宿主` / `--agent 宿主` | 只装到这**一个**宿主 |
| `--hosts 宿主...` | 装到这**几个**宿主，跳过询问 |
| `-d 目录` / `--dir 目录` | 装到指定目录，完全不走宿主探测 |
| `-g` / `--global` | 装到用户级（**默认行为**，写不写都一样） |
| `-p` / `--project` | 只装到当前项目（仅编程类 Agent），版本写进锁文件 |
| `--from 锁文件` | 按锁文件复现：每个 Skill 都切到它记的那个 commit |
| `--force` | 有冲突也覆盖（**覆盖前会先完整备份**） |
| `--no-index` | 不生成 `AGENTS.md` 索引 |
| `--reconfigure` | 重新走一遍首次引导（换仓库、换令牌时用） |

### 2.1.1 交互选择时怎么填

不带参数跑 `skillpm install` 会弹选择框（装哪些 Skill、装到哪些宿主）。每个框都是同一套填法：

| 填什么 | 意思 |
|---|---|
| 直接回车 | 只选**带 `*` 号**的那几个；提示里写明是几个 |
| `a` / `all` / `*` / `全部` | 列表里全部 |
| `1,3,5` / `1 3 5` / `2-4` / `1,3-5` | 只要这几个 |
| 目录路径 | **只在选宿主时**：列表里没有的，直接填 skills 目录，可和序号混填：`1,3 ~/.foo/skills` |
| `0` | 一个都不要 |

`skillpm uninstall` 的选择框**不认 `a`**，只能填序号——删东西不给一键全选。

### 2.2 穷举各种装法

**最常用的三条**

```bash
skillpm install                     # 问你装到哪、装哪几个
skillpm install --all               # 全装，只问装到哪
skillpm install code-review       # 只装这一个
```

**点名装几个**

```bash
skillpm install code-review pdf-tools      # 直接写名字
skillpm install --only code-review pdf-tools   # 等价写法
```

**指定从哪个仓库装**（配了多个仓库时）

```bash
skillpm install --repo 我的库                  # 这个仓库里的全部
skillpm install 我的库:some-skill              # 仓库名:Skill名，点名一个
skillpm install team://我的库/some-skill       # 同上，另一种写法
```

> 同名 Skill 出现在多个仓库时，列表里默认是先配的那个；加仓库前缀就能点名要哪个。
> **已经装了别的仓库的同名 Skill，会先问你要不要换，默认不换**；`--force` 直接换。
> 完整规则见「六、管仓库」里的「多个仓库、同名 Skill」。

**指定装到哪**

```bash
skillpm install -a workbuddy                        # 只装到 WorkBuddy
skillpm install --hosts workbuddy claude-code       # 装到这两个，不问
skillpm install -d ./my-skills                      # 装到指定目录
```

> ⚠️ `--hosts` 会**一路吃到下一个选项为止**，Skill 名要写在它前面：
> `skillpm install code-review --hosts workbuddy` ✅
> `skillpm install --hosts workbuddy code-review` ❌（`code-review` 被当成宿主名）

**强制覆盖：只接管某一个**

目标目录里已经有一份、但不是本工具装的时候，它会跳过并提示。想让它接管：

```bash
skillpm install --force --only doc-writer   # 只动这一个
skillpm install --force                                      # 上面列出的全部接管
```

> **覆盖前会把原来那份完整备份**到 `~/.skillpm/backup/<Skill名>/<版本>-<时间戳>/`，
> 包括工具不认识的文件。加 `--only` 就只动点名的那个，别的一个不碰。

**项目级安装**（只有编程类 Agent 支持）

```bash
cd ~/work/my-project
skillpm install -p                  # 装到 .claude/skills，自动写 skillpm.lock
```

> 在**家目录**里用 `-p` 会被拦下来——`~/.claude/skills` 本来就是用户级目录，
> `-p` 装到的是同一个地方，还会往家目录丢一个 `skillpm.lock`。

**按锁文件复现**

```bash
skillpm install --from team.lock    # 每个 Skill 切到锁里记的 commit 再装
```

**重新配置**

```bash
skillpm install --reconfigure       # 重走首次引导：换仓库地址、换令牌
```

## 三、看现状：三条各看一层

```bash
skillpm status       # 每个宿主装了哪些 Skill、什么版本、有没有被改过
skillpm host list    # 配了哪些宿主、各装了几个、本机还探到哪些
skillpm repo list    # 配了哪些仓库、各有多少 Skill、本机装了几个
```

### 3.1 `skillpm status`

| 参数 | 干什么 |
|---|---|
| `-g` / `--global` | 只看用户级 |
| `-p` / `--project` | 只看当前项目级 |
| `--offline` | 不连仓库，只看本地记录（没网也能跑） |

```
$ skillpm status

工具  skillpm 1.14.2   C:\Users\你\.skillpm
仓库  team  http://gitlab.example.com/team/skills.git   git

WorkBuddy  用户级  C:\Users\你\.workbuddy\skills
  weekly-report               2.6.0     最新   team
  api-tester               1.11.0    最新   team
  pdf-tools               3.3.0     最新   team
```

**排查问题先跑这条**——「我这儿怎么和你不一样」九成能在这看出来。

### 3.2 `skillpm check`

只看，不动任何文件。

| 参数 | 干什么 |
|---|---|
| `--repo 名字` | 只看这个仓库来的 |
| `-u` / `--updatable-only` | 只列可更新的，没有就一句话带过 |

```
$ skillpm check

weekly-report   2.6.0 → 2.6.1    可更新     WorkBuddy
code-review        2.3.1            本地改过   WorkBuddy   ← 更新会被拦下
pdf-tools   3.3.0            最新       WorkBuddy
```

### 3.3 `skillpm host list`

```
$ skillpm host list

已配置
  WorkBuddy          C:\Users\你\.workbuddy\skills      装了 8 个

本机探测到、还没配的
  Codex              C:\Users\你\.codex\skills        verified
  Trae               C:\Users\你\.trae\skills         likely
  foobot             C:\Users\你\.foobot\skills       auto
```

`verified` 是真机上见过或厂商文档写明的目录；`likely` 是按公开对照表推断、**没实地验证过**；
`auto` 是表里没有、但「家目录隐藏文件夹下有 skills」自动发现的。后两种装之前会让你确认。

### 3.4 `skillpm repo list`

```
$ skillpm repo list

skillpm
  地址：http://gitlab.example.com/team/skills.git
  分支：main　方式：git　没配令牌
  缓存：C:\Users\你\.skillpm\repos\skillpm　commit 771222aa
  里面有 8 个 Skill，本机装了 8 个（WorkBuddy）
```

## 四、更新

### 4.1 `skillpm update` —— 更新 **Skill**

| 参数 | 干什么 |
|---|---|
| `--repo 名字` | 只更新来自这个仓库的 |
| `--yes` | 不问直接更新 |
| `--force` | 有冲突也覆盖（先备份） |

不写 `--repo`：所有仓库一起查，但**每个 Skill 只跟它装的时候的来源仓库比**——不弹出来选仓库，
也永远不会被别的仓库的同名 Skill 顶掉。

```
$ skillpm update

有 2 项可以更新
  weekly-report  2.6.0 → 2.6.1   （WorkBuddy）
  code-review       2.3.1 → 2.3.2   （WorkBuddy）

确认更新？ [Y/n]:

更新成功：2 个 Skill

weekly-report  2.6.0 → 2.6.1   WorkBuddy
  ## 2.6.1 — 2026-09-20
  - 测试报告明细页「每一步的log」列宽从 60 调到 80。
  旧版备份：~/.skillpm/backup/weekly-report/2.6.0-20260920-093026
```

> 更新**前**只预告谁要变，完整日志留到更新**成功之后**——没装上的东西不该先把日志给你看。

### 4.2 `skillpm self-update` —— 更新**工具自己**

```bash
skillpm self-update        # 在哪个目录跑都行，不用先 cd
```

别和上面那条搞混：

| 命令 | 更新的是 |
|---|---|
| `skillpm update` | **Skill 内容**（怎么拆用例、怎么出报告……） |
| `skillpm self-update` | **skillpm 工具本身**（命令、参数、提示……） |

### 4.3 `skillpm sync` —— 重建索引

在各宿主目录下重写 `AGENTS.md`（列出装了哪些、什么版本、干什么用）。**不动 Skill 本身。**

```bash
skillpm sync
```

`install` / `update` 会自动生成，一般不用手动跑。手动跑的场景：手改过 `AGENTS.md` 想恢复，或装的时候加了 `--no-index`。

> 索引写在一对标记之间，**标记外面你手写的内容会原样保留**。

## 五、删除（两个，别搞混）

这是最容易搞混的地方，**它们删的不是一个东西**：

| | 删什么 | 命令 | 删完 |
|---|---|---|---|
| **删 Skill** | 装到各 Agent 目录里的 Skill | `skillpm uninstall` | 工具还在，随时能再装回来 |
| **删工具** | skillpm 这个命令本身 | `scripts/uninstall.sh` / `.ps1` | 命令没了，**已装的 Skill 原地不动** |

```
                   skillpm uninstall              scripts/uninstall.sh --all
                          ↓                                   ↓
  ~/.workbuddy/skills/skillpm-*     ← 删这些      ~/.local/bin/skillpm  ← 删这个
  ~/.claude/skills/skillpm-*                      ~/.skillpm/（配置、记录、缓存、备份）
                                                   ~/.skillpm-src/（源码，要手动删）
```

要全清干净，**先删 Skill 再删工具**，见 5.3。

### 5.1 `skillpm uninstall` —— 删 **Skill**

| 参数 | 干什么 |
|---|---|
| `SKILL...` | 要删的 Skill 名，可以写多个 |
| `--only SKILL...` | 同上，写不写都行 |
| `--all` | 删掉**本工具装的**全部 |
| `--host 宿主` | 只动这个宿主（大小写、空格随便写） |
| `--yes` | 不再确认 |

```bash
skillpm uninstall                       # 不写名字：列出来让你勾（默认一个都不选）
skillpm uninstall code-review         # 删这一个
skillpm uninstall flow artifacts        # 删多个
skillpm uninstall --all                 # 全删，会先列清单让你确认
skillpm uninstall --all --yes           # 全删，不确认（脚本里用）
skillpm uninstall --host workbuddy --all   # 只清 WorkBuddy 这一个宿主
```

```
$ skillpm uninstall --all --yes

要移除这些（只动本工具装的，别人放的不碰）
  weekly-report    WorkBuddy   C:\Users\你\.workbuddy\skills\weekly-report
  code-review         WorkBuddy   C:\Users\你\.workbuddy\skills\code-review
  ...
✓ WorkBuddy  weekly-report 已移除
✓ WorkBuddy  code-review 已移除
```

> **它只删自己装的。** 你手动拷进去的那份它认不出来，也就删不掉——
> 那种情况要么自己删目录，要么先 `skillpm install --force --only <名字>` 让它接管。
>
> `--yes` 是「别问我，直接删」。**破坏性操作建议先不加**，看一眼清单再回车。

### 5.2 `scripts/uninstall.sh` / `.ps1` —— 删**工具本身**

**Mac / Linux**

```bash
~/.skillpm-src/scripts/uninstall.sh           # 只卸工具，配置和已装的 Skill 都留着
~/.skillpm-src/scripts/uninstall.sh --all     # 连 ~/.skillpm 一起删
```

**Windows**

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
& "$env:USERPROFILE\.skillpm-src\scripts\uninstall.ps1"         # 只卸工具
& "$env:USERPROFILE\.skillpm-src\scripts\uninstall.ps1" -All    # 连 .skillpm 一起删
```

| 参数 | 删什么 | 不删什么 |
|---|---|---|
| （不加） | 启动器 / pip 包 | `~/.skillpm`（配置、安装记录、缓存、备份）、已装的 Skill |
| `--all` / `-All` | 上面那些 **＋ `~/.skillpm`** | 已装的 Skill、`~/.skillpm-src` 源码 |

加 `--all` / `-All` 时会**明确问你一次**（`要删掉 ... 吗？[y/N]`），这个没有跳过的参数。

它**不动**已经装到各宿主目录里的 Skill，也**不动 PATH**里那条目录
（指向一个空目录而已，无害；想清就自己去环境变量里删）。

源码目录要手动删：

```bash
rm -rf ~/.skillpm-src                                    # Mac
Remove-Item -Recurse -Force $env:USERPROFILE\.skillpm-src   # Windows
```

### 5.3 完整清理（三步，顺序别反）

```bash
# Mac / Linux
skillpm uninstall --all --yes
~/.skillpm-src/scripts/uninstall.sh --all
rm -rf ~/.skillpm-src
```

```powershell
# Windows
skillpm uninstall --all --yes
Set-ExecutionPolicy -Scope Process Bypass -Force; & "$env:USERPROFILE\.skillpm-src\scripts\uninstall.ps1" -All
Remove-Item -Recurse -Force $env:USERPROFILE\.skillpm-src
```

## 六、管仓库：`skillpm repo`

> **别的团队**要接自己的 Skill 仓库，看 [接入自己的Skill仓库.md](接入自己的Skill仓库.md)，从整理仓库到加进来一步步都有。

```bash
skillpm repo                                              # 不写动作＝列出已配的，顺带给常用写法
skillpm repo add 我们团队 http://gitlab.example.com/组/仓库.git        # 地址直接写，http/git@ 自动认
skillpm repo add 我们团队 git@gitlab.example.com:组/仓库.git
skillpm repo add 我们团队 http://gitlab.example.com/组/仓库.git --token <令牌>   # 私有仓库
skillpm repo add 我们团队 http://gitlab.example.com/组/仓库.git --branch dev     # 不是 main 分支
skillpm repo remove 我们团队                               # 只删配置，不动已装的 Skill
```

**`repo add` 会先试拉一次**：拉得到、里面有能装的 Skill 才保存，并告诉你有几个；
拉不到就说清楚是哪种原因（要登录／找不到仓库／连不上／端口不对／SSH 没过／没有这个分支／没有能装的 Skill），**不保存**。
同名再 `add` 一次就是改地址、改令牌。

| 参数 | 干什么 |
|---|---|
| `<名字> <地址>` | 名字自己起；地址写 `http(s)://…/组/仓库(.git)` 或 `git@主机:组/仓库.git` |
| `--token 令牌` | 私有仓库的访问令牌。**屏幕输出和报错里一律打码** |
| `--branch 分支` | 默认 `main` |
| `--no-check` | 不试拉，直接记下（离线时配置用） |
| `--http-only` | 不用 git，下载压缩包（要令牌） |
| `--ssh 地址` / `--http 地址` / `--path 组/项目` | 旧写法，照样能用；地址直接写在名字后面更省事 |
| `--yes` | `remove` 时不再确认 |

配好之后这些命令都能限定范围：`install --repo`、`check --repo`、`update --repo`。

### 多个仓库、同名 Skill：规则就两条

同一个 Agent 下，同名的 Skill **只能留一个**。可以从多个仓库装，平时名字不会撞；撞了按下面两条走：

**① 换来源只发生在你自己 `install` 的时候，而且一定先问你**

| 情况 | 结果 |
|---|---|
| 不重名 | 正常装 |
| 同一个仓库重装、升级 | 正常装，不问 |
| 已装的 A 来自甲，这次要装乙的 A | 停下来问，**默认不换**：<br>回 `y` → 覆盖成乙的，以后跟着乙更新<br>回 `n`（或直接回车）→ 跳过，还是甲的 |
| 不想被问 | `skillpm install 乙:A --force`（只换这一个）<br>`skillpm install --repo 乙 --force`（乙的全换） |
| 脚本、CI 里没法回答 | 默认不换，退出码 1，提示加 `--force` |

```
! WorkBuddy：A 现在装的是「甲」的 1.0.0，这次要换成「乙」的 5.0.0
  同一个 Agent 下同名的只能留一个；换了以后就跟着新仓库更新
  确定换吗？[y/N]
```

**② `update` 永远不换来源**

每个装上的 Skill 都记着「从哪个仓库装的」，`update` 只拿它跟那个仓库比：

- 不写 `--repo`：所有仓库都拉一遍，但 **A 只跟甲比、B 只跟乙比**，别的仓库里有没有同名的都不影响。
  不会弹出来让你选仓库——每个 Skill 该跟哪个仓库，装的时候就定了。
- 写 `--repo 乙`：只更新从乙装的那些。
- 只更新你装过的；仓库里新加的、你没装过的不会自己装上。
- 来源仓库被 `repo remove` 了、或者里面没有这个 Skill 了：**不更新、说明原因**，不拿别的仓库的同名 Skill 顶上。

为什么两条都要：只有 ① 不够。比如从乙装了 A，后来又加了个仓库丙、里面恰好也有 A——
你没去装丙的 A，① 根本不会触发；是 ② 保证了 `update` 只认乙。

> 1.20.1 之前 `update` 按名字找、先配的仓库优先：从乙装的 A 会被悄悄换成甲的，版本还可能倒退。
> 1.20.2 之前 `install` 换来源不问，直接顶掉。现在两处都修了。

## 六·五、检查自己的仓库：`skillpm manifest`

仓库要能被安装，**只要一条**：Skill 放在 `skills/<名字>/SKILL.md`，开头 frontmatter 里写 `name`（和目录名一样）和 `description`；`version` 可选。
**不需要任何配置文件**——`manifest.json` 是可选的：没有就按 `skills/` 当场算，有就用它。

```bash
skillpm manifest --check            # 只检查：每个 Skill 合不合格；有 manifest.json 的话再查它是不是最新。不合格退出码 1（CI 用）
skillpm manifest                    # 生成 manifest.json（可选；生成了就得每次改完都重新生成）
skillpm manifest ~/code/我们的仓库   # 指定目录
```

| 检查项 | 不满足时 |
|---|---|
| 有 `skills/` 目录，里面至少一个 `SKILL.md` | 报错 |
| `SKILL.md` 有 frontmatter，`name` 和目录名一致 | 报错 |
| 写了 `description` | 提醒 |
| 写了 `version`（顶层或 `metadata:` 下都行）；不写就按文件内容判断更新 | 提醒 |
| 有 `CHANGELOG.md`，且有当前版本那一节 | 提醒 |
| （有 manifest.json 时）它和 `skills/` 对得上，没有「文件改了、版本号没动」 | 报错 |

不合格的 Skill 装的时候会被跳过并提示原因，同一个仓库里别的 Skill 照常能装。

## 七、管宿主：`skillpm host`

```bash
skillpm host list                           # 已配的 + 本机探到还没配的
skillpm host add 我的工具 ~/.mytool/skills   # 自己加一个（不在目录表里的）
skillpm host remove 我的工具                 # 只删配置，不动目录里的文件
```

宿主表是**累积的注册表**：装到 B 不会把上次配的 A 删掉，只有 `host remove` 才删。

目录表里认识 52 种常见 Agent：

| 可信度 | 有哪些 |
|---|---|
| `verified`（真机见过或厂商文档写明） | Claude Code、Codex、WorkBuddy、WorkBuddy-AI、Qoder、Cursor、Windsurf、Gemini CLI、Antigravity、Grok、Agents、Comate |
| `likely`（按公开对照表推断） | Trae、Trae CN、Qoder CN、Lingma、CodeBuddy、Qwen Code、iFlow、CodeArts、MiniMax Code、ZCode、JoyCode、Codemaker、Neovate、GitHub Copilot、OpenCode、Amp、Droid、Kiro、Kilo Code、Roo Code、Continue、Augment、Junie、Goose、Crush、OpenHands、Mistral Vibe、Devin、Rovo Dev、Tabnine、Cortex Code、IBM Bob、Hermes Agent、OpenClaw、Pi、AiderDesk、ForgeCode、Zencoder、Firebender、Deep Agents |
| `auto`（自动发现） | 不在表里、但家目录隐藏文件夹下有 `skills` 目录的 |

## 八、锁版本：`skillpm freeze` + `install --from`

**要解决的问题**：你装的 2.3.1 和我装的 2.3.1，内容不一定一样——「装的时候仓库 HEAD 是什么」一直在动。锁文件记的是 **commit**，所以能真正复现。

| `freeze` 参数 | 干什么 |
|---|---|
| `-o 文件` / `--out 文件` | 输出到哪，默认当前项目的 `skillpm.lock` |
| `--host 宿主` | 只导这个宿主装的 |

```bash
skillpm freeze -o team.lock         # 你（定基线的人）
skillpm install --from team.lock    # 别人，装回完全一样的一套
```

> 项目级安装（`-p`）会**自动**写 `skillpm.lock`；用户级**不自动写**——
> 个人偏好不该污染别人的配置，要共享就显式 `freeze` 一份。

## 九、装/更新工具本身的脚本参数

**Mac / Linux —— `scripts/install.sh`**

| 写法 | 干什么 |
|---|---|
| `./scripts/install.sh` | 自动挑一种能用的装法（默认＝启动器） |
| `./scripts/install.sh --launcher` | 强制只做启动器（最快，零网络） |
| `./scripts/install.sh --pip` | 强制用 pip（要能连 PyPI） |
| `PREFIX=/some/bin ./scripts/install.sh` | 指定装到哪个目录 |

**Windows —— `scripts\install.ps1`**

| 参数 | 干什么 |
|---|---|
| `-Mode launcher` | 只做启动器（默认） |
| `-Mode pip` | 用 pip 装 |
| `-Prefix D:\bin` | 指定装到哪 |
| `-Yes` | 不弹任何询问，PATH 直接加（批量铺开、CI 用） |

**重复运行就是更新**：脚本会先 `git pull` 再重新链接，所以「装」和「更新」是同一条命令。

> ⚠️ Windows 上**用 `&` 调用，别用 `powershell -File`**：
> `-File` 会另起一个进程，它改的 `$env:PATH` 传不回你的窗口，装完得重开终端。
> `&` 是在当前会话里跑，装完直接就能敲 `skillpm`。

## 十二、文件都放在哪

```
~/.skillpm-src/            工具源码（写死的位置，self-update 去这儿拉）
~/.skillpm/
  ├── config.json           仓库地址、令牌、宿主路径（权限 600）
  ├── state.json            装了什么、什么版本、安装时每个文件的哈希
  ├── repos/<仓库名>/       各仓库的本地缓存
  └── backup/               更新和覆盖前的旧版，想回退直接拷回去
<项目根>/skillpm.lock      项目级安装自动写的锁文件
<宿主目录>/AGENTS.md        装了哪些 Skill 的索引
```

Windows 对应 `%USERPROFILE%\.skillpm-src`、`%USERPROFILE%\.skillpm`。

## 附录：一条命令合集

**装工具（也是更新工具）**

```bash
# Mac / Linux
git clone https://github.com/suqian-bit/skillpm.git ~/.skillpm-src 2>/dev/null; ~/.skillpm-src/scripts/install.sh
```

```powershell
# Windows
if (-not (Test-Path $env:USERPROFILE\.skillpm-src)) { git clone https://github.com/suqian-bit/skillpm.git $env:USERPROFILE\.skillpm-src }; Set-ExecutionPolicy -Scope Process Bypass -Force; & "$env:USERPROFILE\.skillpm-src\scripts\install.ps1"
```

两条都**重复跑也没事**，不需要 SSH key、不需要令牌，只要有 git 和 Python 3.8+。

**日常**

```bash
skillpm install     # 装
skillpm check       # 看看有没有新的
skillpm update      # 跟上
skillpm status      # 现在装了什么
```
