# skillpm —— AI Skill 的安装与版本治理

> 基于 Git 的 Skill 分发工具：一条命令装到任意 Agent 宿主，跟着仓库更新，
> 用锁文件让全组对齐到同一份。Mac / Windows / Linux 通用，零第三方依赖，不需要外网。

---

## 写在前面

### 30 秒了解 skillpm

一句话：**skillpm 是 AI Skill 的包管理器**，帮你像管代码依赖一样管 Skill。

Skill 本身放在你们团队的 Git 仓库里，skillpm 负责把它们
取下来、装进你正在用的 Agent（WorkBuddy、Claude Code、Cursor……）、跟着仓库更新、
出冲突时报给你而不是替你决定。

**先跑起来（2 分钟）：**

```bash
# 1. 装工具（一条命令，重复跑也没事）
git clone https://github.com/suqian-bit/skillpm.git ~/.skillpm-src 2>/dev/null; ~/.skillpm-src/scripts/install.sh

# 2. 装 Skill（第一次会引导你选仓库、选装到哪个 Agent、选装哪几个）
skillpm install

# 3. 打开 WorkBuddy / Claude Code，直接说：
#    "帮我把这份需求拆成测试用例"
```

**日常就两条：**

```bash
skillpm check      # 看看有没有新版本，什么都不动
skillpm update     # 跟上最新，并告诉你每个 Skill 改了什么
```

## 一、它解决什么问题

| 没有它的时候 | 有了它之后 |
|---|---|
| Skill 靠群里发压缩包，谁装了哪个版本没人知道 | `skillpm status` 一眼看清每个宿主装了什么、什么版本 |
| 改了 Skill 要挨个通知，总有人还在用旧的 | `skillpm update` 自己拉，还会把改了什么念给你听 |
| 换台机器、换个 Agent，又得重装一遍 | 装到哪由你勾选，配置记在 `~/.skillpm/`，换机器重跑一条命令 |
| "我这儿能跑你那儿不行"——其实版本不一样 | `freeze` 出锁文件，别人 `install --from` 装回**完全一样**的一套 |
| 本地改过的 Skill 一更新就被冲掉 | 装的时候记了每个文件的哈希，改过就拦下来给你看 diff |

**边界**：skillpm 只管分发和版本，**不管 Skill 写得对不对**。
Skill 内容、评测、回归在另一个仓库里做。

## 二、安装工具本身

源码固定放在 **`~/.skillpm-src`**（Windows 是 `%USERPROFILE%\.skillpm-src`）——
写死的，省得每次找不着。

### 2.1 Mac / Linux

```bash
git clone https://github.com/suqian-bit/skillpm.git ~/.skillpm-src 2>/dev/null; ~/.skillpm-src/scripts/install.sh
```

中间是 `;` 不是 `&&`：目录已经在了，克隆那步失败也不影响后面照样装。
**这条命令重复跑也没事**，脚本会自己拉最新再重新链接。

### 2.2 Windows（PowerShell）

```powershell
if (-not (Test-Path $env:USERPROFILE\.skillpm-src)) { git clone https://github.com/suqian-bit/skillpm.git $env:USERPROFILE\.skillpm-src }; Set-ExecutionPolicy -Scope Process Bypass -Force; & "$env:USERPROFILE\.skillpm-src\scripts\install.ps1"
```

同样可以重复跑。

> ⚠️ Windows 脚本按 PowerShell 5.1 写的，但**还没在真机上跑过**。
> 第一个在 Windows 上装的同事麻烦反馈一下，有问题我当天改。

### 2.3 装完确认

```bash
skillpm -v
# → skillpm 1.10.0
```

提示 `command not found`，说明装的位置不在 PATH 里。安装脚本会主动问你要不要加，
回车同意即可（Mac 写 `.zshrc`/`.bashrc`，Windows 写用户 PATH），**新开一个终端**生效。

### 2.4 为什么不用 pip install

有的公司网络访问 pypi.org 要 8 秒以上甚至超时，国内镜像也不一定快。
默认的安装脚本**一个网络包都不下**：只要本机有 Python 3.8+ 就能装完。

想走 pip 也行（需要能连 PyPI）：

| 方式 | 命令 | 说明 |
|---|---|---|
| 启动器（默认） | `scripts/install.sh` | 生成一个小启动脚本指向源码，零依赖、零网络 |
| 只生成启动器 | `scripts/install.sh --launcher` | 跳过其它步骤 |
| 走 pip | `scripts/install.sh --pip` | 标准 `pip install -e`，要能连 PyPI |

### 2.5 更新工具自己

```bash
skillpm self-update
```

**在哪个目录跑都行**——它知道自己的源码在 `~/.skillpm-src`，不用先 `cd` 过去。
更新完会把这中间的改动打给你看。

### 2.6 卸载工具

```bash
~/.skillpm-src/scripts/uninstall.sh           # 只卸工具，已装的 Skill 不动
~/.skillpm-src/scripts/uninstall.sh --all     # 连 ~/.skillpm（配置/状态/缓存/备份）一起删
```

Windows：`powershell -ExecutionPolicy Bypass -File $env:USERPROFILE\.skillpm-src\scripts\uninstall.ps1 [-All]`

想连 Skill 一起清干净，**顺序是先清 Skill、再卸工具**：

```bash
skillpm uninstall --all --yes                 # 先移除它装的 Skill
~/.skillpm-src/scripts/uninstall.sh --all     # 再卸工具
```

反过来不行——工具没了，就没人知道哪些 Skill 是它装的了。

## 三、先认识四个概念

### 3.1 仓库（Repo）—— Skill 从哪来

一个 Git 仓库，Skill 放在 `skills/<名字>/SKILL.md` 下（通用 Agent Skill 格式：`name`、`description`，`version` 可选）。根目录的 `manifest.json` 可选，没有就按 `skills/` 当场算。
**可以配多个**，各自独立的分支和鉴权。第一次运行时配第一个。

### 3.2 宿主（Host）—— Skill 装到哪去

你在用的 Agent 工具。目录表里认识 52 种，探测出来**由你勾选**，
不是探到几个装几个。不在表里的自己 `host add`。

### 3.3 用户级 / 项目级 —— 装的范围

**默认用户级**，因为绝大多数 Agent 就是全局生效的，压根没有"项目"这个概念。
只有在仓库里干活的编程类 Agent（Claude Code、Codex、Cursor……）才额外支持项目级，
`install -p` 对不支持的宿主会直接报错，而不是瞎建个目录糊弄你。

### 3.4 安装记录与锁文件 —— 凭什么知道谁装了什么

`~/.skillpm/state.json` 记着**每个文件安装时的哈希**。所以它能分清三件事：
这是我装的没动过 / 这是我装的但你改了 / 这压根不是我装的。
锁文件（`skillpm.lock`）记的是 **commit**，不是版本号——同一个版本号的内容也可能被改过。

```
┌──────────────────────── Skill 解析流程 ────────────────────────┐
│                                                                │
│   Git 仓库（可多个）                                            │
│   团队仓库            我的库       …                           │
│        │                 │                                     │
│        └────────┬────────┘                                     │
│                 ▼                                              │
│        ~/.skillpm/repos/<仓库名>/      ← 本地缓存，按需 fetch   │
│                 │                                              │
│                 ▼                                              │
│        manifest.json  ← 可选：有哪些 Skill、版本、文件哈希     │
│                 │                                              │
│        ┌────────┴────────┐                                     │
│        ▼                 ▼                                     │
│   用户级（默认）      项目级（仅编程类 Agent）                   │
│   ~/.workbuddy/skills   <项目根>/.claude/skills                 │
│   ~/.claude/skills      <项目根>/.codex/skills                  │
│   ~/.cursor/skills      + 自动写 skillpm.lock                  │
│        │                                                       │
│        ▼                                                       │
│   ~/.skillpm/state.json  ← 谁装的、什么版本、装时的文件哈希      │
│        │                                                       │
│        ├─ 哈希一致        → 干净，可以直接更新                   │
│        ├─ 哈希不一致      → 你改过，报 diff、跳过、等你决定       │
│        └─ 记录里根本没有  → 别人放的，一律不动                   │
└────────────────────────────────────────────────────────────────┘
```

## 四、命令详解（每个功能怎么用）

> 只想查某个参数怎么写，看 [命令手册](命令手册.md)——那份是穷举的速查表。
> 这一章讲的是每条命令**为什么这么设计**。

全局参数：`-v` / `-V` / `--version` 看版本，`-h` / `--help` / `-help` 看帮助
（单横线的 `-help`、`-version` 也认）。每个子命令后面加 `-h` 都能看到自己的参数。

命令名或参数打错了会给猜测，不会只丢一句 "unrecognized arguments"：

```
$ skillpm install --hots workbuddy
✗ 没有 --hots 这个参数
  是不是想写 --hosts  或  --host？
  看全部用法：skillpm <命令> -h
```

### 4.1 `skillpm install` —— 安装

**干什么**：从仓库取 Skill，装到你选的宿主目录。

**第一次跑**会先引导两步：
1. **Skill 仓库**：先问地址（必填，你们团队放 Skill 的仓库），再问起个名字（默认取地址里的组名），
   然后**当场试拉一次**——拉得到才往下走；拉不到会说原因、让你重填；私有仓库会问你要访问令牌。
2. **装到哪**：列出本机探到的 Agent，下一步让你勾选。

```bash
skillpm install                       # 最常用：问你装到哪、装哪几个
skillpm install --all                 # 全装，不问装哪几个
skillpm install code-review         # 只装这一个（可以写多个名字）
```

| 参数 | 作用 |
|---|---|
| `SKILL...` | 要装的 Skill 名，写多个用空格分开 |
| `--only SKILL...` | 同上，写不写 `--only` 都行 |
| `--all` | 全装，跳过"装哪几个"的询问 |
| `--repo 名字` | 只装这个仓库里的 |
| `-a 宿主` / `--agent 宿主` | 只装到这一个宿主 |
| `--hosts 宿主...` | 装到这几个宿主，跳过询问 |
| `-d 目录` / `--dir 目录` | 装到指定目录，完全不走宿主探测 |
| `-p` / `--project` | 装到当前项目（仅编程类 Agent），版本写进锁文件随项目提交 |
| `-g` / `--global` | 装到用户级（默认行为，写不写都一样） |
| `--from 锁文件` | 按锁文件复现：每个 Skill 都切到它记的那个 commit |
| `--force` | 有冲突也覆盖（**覆盖前会先完整备份**） |
| `--no-index` | 不生成 `AGENTS.md` 索引 |
| `--reconfigure` | 重新走一遍引导（换仓库、换令牌时用） |

**装到哪，每次都会问**，上次选的默认勾好，回车沿用：

```
$ skillpm install

装到哪些宿主？
  * 1. WorkBuddy       /Users/you/.workbuddy/skills
  * 2. WorkBuddy-AI    /Users/you/.workbuddy-ai/skills
    3. Claude Code     /Users/you/.claude/skills      （本机探到，还没配过）
    4. Cursor          /Users/you/.cursor/skills      （本机探到，还没配过）
回车＝只选带 * 号的这 2 个；a＝全部 4 个；只要其中几个就填序号（1,3,5 或 2-4）；列表里没有就直接填目录路径；0＝都不要:
```

每个选择框都是同一套填法：

| 填什么 | 意思 |
|---|---|
| 直接回车 | 只选**带 `*` 号**的那几个（上次选的）。提示里会写明是哪几个、几个 |
| `a`（或 `all`、`*`、`全部`） | 列表里**全部** |
| `1,3,5` / `1 3 5` / `2-4` / `1,3-5` | 只要这几个，逗号、空格、范围都行 |
| 一个目录路径 | 列表里没有的宿主，直接填它的 skills 目录，比如 `~/.foo/skills`、`C:\Users\你\.foo\skills`；可以和序号混着填：`1,3 ~/.foo/skills` |
| `0` | 一个都不要 |

手填路径的细节：
- 名字自动起：`~/.foo/skills` 记为宿主「foo」；表里认识的目录用表里的名字；重名但不是同一个目录会加 `-2`。
- 填的是 Agent 文件夹本身（`~/.foo`）而它下面有 `skills`，会问一句是不是装进 `skills`。
- 目录不存在会问要不要新建，**默认不建**，防手滑打错字。
- 只有「选宿主」的框认路径；选 Skill、选仓库、卸载的框里填路径会让你重填。
- **卸载不给 `a`**：删是危险动作，一个键删光不行，得填序号。

不想被问：`--hosts workbuddy claude-code`，或者 `-a workbuddy` 只装一个。
管道里跑、CI 里跑不会弹询问，直接用已配的。

> ⚠️ `--hosts` 会**一路吃到下一个选项为止**，所以 Skill 名要写在它前面：
> `skillpm install code-review --hosts workbuddy` ✅
> `skillpm install --hosts workbuddy code-review` ❌（`code-review` 被当成宿主名，
> 会报「不认识这些宿主」并提醒你调词序）

**点名装某个仓库里的某个 Skill**（同名 Skill 出现在多个仓库时用得上）：

```bash
skillpm install 我的库:some-skill           # 仓库名:Skill名
skillpm install team://我的库/some-skill    # 同一个意思，另一种写法
```

**装到一个随便指定的目录**（调试、或者给没进目录表的工具用）：

```bash
skillpm install -d ./my-skills --only code-review
```

> 还没接的安装源：`owner/repo/skill`（GitHub）、git 地址、本地路径。
> 写了会明确告诉你没接，并提示先 `repo add` 再装——不会装成功的样子。

### 4.2 `skillpm check` —— 只看，不动

**干什么**：对比本地和仓库，列出谁能更新、谁被你改过。**什么都不会动。**

```bash
skillpm check                   # 看所有仓库
skillpm check --repo 我的库     # 只看这个仓库来的
skillpm check -u                # 只列可更新的，没有就一句话带过
```

| 参数 | 作用 |
|---|---|
| `--repo 名字` | 只看这个仓库来的 |
| `-u` / `--updatable-only` | 只列可更新的 |

```
$ skillpm check

weekly-report   2.6.0 → 2.6.1    可更新     WorkBuddy
code-review        2.3.1            本地改过   WorkBuddy   ← 更新会被拦下
pdf-tools   3.3.0            最新       WorkBuddy
```

适合塞进每天开工的第一条命令，或者 CI 里做个提醒。

---

### 4.3 `skillpm update` —— 跟上最新

**干什么**：检查更新，确认后拉下来装上，**并把每个 Skill 改了什么念给你听**。

```bash
skillpm update                  # 问一下再更新
skillpm update --yes            # 不问直接更新
skillpm update --repo 我的库    # 只更新来自这个仓库的
```

| 参数 | 作用 |
|---|---|
| `--repo 名字` | 只更新来自这个仓库的 |
| `--yes` | 不再确认 |
| `--force` | 有冲突也覆盖（先备份） |

不写 `--repo` 就是所有仓库一起查，但**每个 Skill 只跟它自己的来源仓库比**，不会弹出来让你选仓库，
也不会被别的仓库的同名 Skill 顶掉（见「多个仓库、同名 Skill」）。

```
$ skillpm update

有 2 项可以更新
  weekly-report  2.6.0 → 2.6.1   （WorkBuddy）
  code-review       2.3.1 → 2.3.2   （WorkBuddy）

确认更新？ [Y/n]:

更新成功：2 个 Skill

weekly-report  2.6.0 → 2.6.1   WorkBuddy
  ## 2.6.1 — 2026-09-20
  - 测试报告明细页「每一步的log」列宽从 60 调到 80，长执行记录不再被挤成一条线。
  旧版备份：~/.skillpm/backup/weekly-report/2.6.0-20260920-093026
```

> **设计考量**：更新**前**只预告谁要变，完整的更新日志留到更新**成功之后**才打。
> 没装上的东西不该先把日志给你看——那会让人以为已经生效了。

---

> **想知道"我现在是个什么状况"，三条各看一层：**
> `status` 看每个宿主装了哪些 Skill、什么版本；
> `host list` 看配了哪些宿主、各装了几个；
> `repo list` 看配了哪些仓库、各有多少 Skill、本机装了几个。

### 4.4 `skillpm status` —— 装了什么

**干什么**：各宿主装了什么、什么版本、来自哪个仓库、有没有被本地改过。

```bash
skillpm status                  # 全部
skillpm status -g               # 只看用户级
skillpm status -p               # 只看当前项目级
skillpm status --offline        # 不连仓库，只看本地（没网也能跑）
```

| 参数 | 作用 |
|---|---|
| `-g` / `--global` | 只看用户级 |
| `-p` / `--project` | 只看当前项目级 |
| `--offline` | 不连仓库，只看本地记录 |

```
$ skillpm status

工具  skillpm 1.10.0   /Users/you/.skillpm
仓库  team　git@gitlab.example.com:team/skills.git   git

WorkBuddy  用户级  /Users/you/.workbuddy/skills
  weekly-report               2.6.0     最新   team
  api-reader                1.10.2    最新   team
  api-tester               1.10.2    最新   team
  pdf-tools               3.3.0     最新   team
  code-review                    2.3.1     最新   team
```

排查问题先跑这条：**"我这儿怎么和你不一样"，九成能在这儿看出来。**

### 4.5 `skillpm uninstall` —— 移除 Skill

**干什么**：移除本工具装的 Skill。**只动自己装的**，别人放的一律不碰。

```bash
skillpm uninstall                       # 不写名字：列出来让你选
skillpm uninstall code-review         # 移除这一个
skillpm uninstall flow artifacts        # 移除多个
skillpm uninstall --all                 # 全删（本工具装的那些）
skillpm uninstall --all --yes           # 全删，不再确认
skillpm uninstall --host workbuddy      # 只动这个宿主
```

| 参数 | 作用 |
|---|---|
| `SKILL...` | 要移除的 Skill 名，可以写多个 |
| `--only SKILL...` | 同上，写不写都行 |
| `--all` | 移除本工具装的全部 |
| `--host 宿主` | 只动这个宿主（大小写、空格随便写） |
| `--yes` | 不再确认 |

> 这条**卸不掉不是本工具装的那份**——它只认安装记录。
> 遇到那种情况看 [第六章](#六冲突怎么处理)。

### 4.6 `skillpm repo` —— 管理 Skill 仓库

**干什么**：增删查 Skill 仓库，**可以配多个**，各自独立分支和鉴权。

```bash
# 地址直接写在名字后面，http 和 git@ 自动认
skillpm repo add 我的库 http://gitlab.example.com/组/仓库.git
skillpm repo add 我的库 git@gitlab.example.com:组/仓库.git

# 私有仓库带令牌；不是 main 分支用 --branch
skillpm repo add 我的库 http://gitlab.example.com/组/仓库.git --token <令牌>
skillpm repo add 我的库 http://gitlab.example.com/组/仓库.git --branch dev

skillpm repo                    # 看已配的（等于 repo list）
skillpm repo remove 我的库      # 删掉（只删配置，不动已装的 Skill）
```

`repo add` 会**先试拉一次**，拉得到、里面有能装的 Skill 才保存；拉不到会说清楚是哪种原因，不保存。

```
$ skillpm repo list

skillpm
  地址：git@gitlab.example.com:team/skills.git
  分支：main　方式：git　没配令牌
  缓存：/Users/you/.skillpm/repos/skillpm　commit 33cad700
  里面有 8 个 Skill，本机装了 8 个（WorkBuddy、WorkBuddy-AI）

  看每个宿主装了哪些：skillpm status；只装某个仓库的：skillpm install --repo <名字>
```

| 参数 | 作用 |
|---|---|
| `--ssh 地址` | SSH 地址，如 `git@host:group/proj.git` |
| `--http 地址` | GitLab 网页地址，如 `http://gitlab.example.com`（也可以直接把完整地址写在仓库名后面） |
| `--path 路径` | 项目路径，如 `group/proj`（配合 `--http`） |
| `--branch 分支` | 分支，默认 `main` |
| `--token 令牌` | 访问令牌（HTTP 方式要）。**屏幕输出和报错里一律打码** |
| `--http-only` | 强制走 HTTP 下载，不用 git（机器上没装 git 时） |
| `--yes` | 不再确认 |

配好之后，这些命令都能按仓库限定范围：

```bash
skillpm install --repo 我的库
skillpm check   --repo 我的库
skillpm update  --repo 我的库
```

**仓库要能被安装只要一条**：Skill 放在 `skills/<名字>/SKILL.md`，开头 frontmatter 写好 `name`（和目录名一样）和 `description`；`version` 建议写，不写就按文件内容判断更新。
`manifest.json` 可选（`skillpm manifest` 生成）；没有就按 `skills/` 当场算。别的团队接自己的仓库，完整步骤见
[接入自己的Skill仓库.md](接入自己的Skill仓库.md)。
同名 Skill 出现在多个仓库时怎么处理，见下面这节。

### 多个仓库、同名 Skill：规则就两条

同一个 Agent 下，同名的 Skill **只能留一个**。可以从多个仓库装，平时名字不会撞；撞了按下面两条走：

**① 换来源只发生在你自己 `install` 的时候，而且一定先问你**

| 情况 | 结果 |
|---|---|
| 不重名 | 正常装 |
| 同一个仓库重装、升级 | 正常装，不问 |
| 已装的 A 来自甲，这次要装乙的 A | 停下来问，**默认不换**：<br>回 `y` → 覆盖成乙的，以后跟着乙更新<br>回 `n`（或直接回车）→ 跳过，还是甲的 |
| 不想被问 | `skillpm install 乙:A --force`（只换这一个）<br>`skillpm install --repo 乙 --force`（乙的全换） |
| 脚本、CI 里没法回答 | 默认不换，退出码 1，提示加 `--force` |

```
! WorkBuddy：A 现在装的是「甲」的 1.0.0，这次要换成「乙」的 5.0.0
  同一个 Agent 下同名的只能留一个；换了以后就跟着新仓库更新
  确定换吗？[y/N]
```

**② `update` 永远不换来源**

每个装上的 Skill 都记着「从哪个仓库装的」，`update` 只拿它跟那个仓库比：

- 不写 `--repo`：所有仓库都拉一遍，但 **A 只跟甲比、B 只跟乙比**，别的仓库里有没有同名的都不影响。
  不会弹出来让你选仓库——每个 Skill 该跟哪个仓库，装的时候就定了。
- 写 `--repo 乙`：只更新从乙装的那些。
- 只更新你装过的；仓库里新加的、你没装过的不会自己装上。
- 来源仓库被 `repo remove` 了、或者里面没有这个 Skill 了：**不更新、说明原因**，不拿别的仓库的同名 Skill 顶上。

为什么两条都要：只有 ① 不够。比如从乙装了 A，后来又加了个仓库丙、里面恰好也有 A——
你没去装丙的 A，① 根本不会触发；是 ② 保证了 `update` 只认乙。

> 1.20.1 之前 `update` 按名字找、先配的仓库优先：从乙装的 A 会被悄悄换成甲的，版本还可能倒退。
> 1.20.2 之前 `install` 换来源不问，直接顶掉。现在两处都修了。

### 4.7 `skillpm host` —— 管理宿主目录

**干什么**：看认识哪些 Agent、本机探到哪些、自己加没在表里的。

```bash
skillpm host list                          # 已配的 + 本机探到还没配的
skillpm host add 我的工具 ~/.mytool/skills # 自己加一个
skillpm host remove 我的工具               # 删掉（只删配置，不动目录里的文件）
```

```
$ skillpm host list

已配置
  WorkBuddy          /Users/you/.workbuddy/skills       装了 8 个
  WorkBuddy-AI       /Users/you/.workbuddy-ai/skills    装了 8 个
  Claude Code        /Users/you/.claude/skills          还没装东西

本机探测到、还没配的
  Codex              /Users/you/.codex/skills         verified
  Cursor             /Users/you/.cursor/skills        likely

  目录表里认识 52 种宿主；不在表里、但家目录隐藏文件夹下有 skills 的自动发现；
  再不行用 skillpm host add <名字> <路径> 自己加
  想看每个宿主里具体装了哪些 Skill、什么版本：skillpm status
```

**宿主表是累积的**：装到 B 不会把上次配的 A 删掉，只有 `host remove` 才删。
（1.10.0 之前会覆盖，所以老配置可能少了宿主——装过的会自动找回来并标黄提示。）

`verified` 是在真机上见过的，`likely` 是按公开约定推断、**没实地验证过**——
会标出来让你自己确认，不会闷声装进去。完整对照表见[附录 B](#附录-b宿主对照表)。

### 4.8 `skillpm freeze` + `install --from` —— 让全组装到完全一样的东西

**要解决的问题**：你装的 2.3.1 和我装的 2.3.1，内容不一定一样——
因为"装的时候仓库 HEAD 是什么"一直在动。锁文件记的是 **commit**，所以能真正复现。

```bash
# 你（定基线的人）：装好之后导出
skillpm freeze -o team.lock

# 别人：按它装回完全一样的一套
skillpm install --from team.lock
```

| `freeze` 参数 | 作用 |
|---|---|
| `-o 文件` / `--out 文件` | 输出到哪，默认当前项目的 `skillpm.lock` |
| `--host 宿主` | 只导这个宿主装的 |

`--from` 会把仓库**切到锁里记的那个 commit** 再装。哪怕仓库已经往前走了好几个版本，
装到的仍然是锁里那个——这点专门验证过（仓库推到 2.3.2，按锁装出来还是 2.3.1）。

`team.lock` 放进项目仓库、发群里、放共享目录都行。

> **设计考量**：项目级安装（`-p`）会**自动**在项目根写 `skillpm.lock`，不用手动 freeze；
> 用户级安装**不自动写**——个人偏好不该污染别人的配置，要共享就显式 `freeze` 一份。

### 4.9 `skillpm sync` —— 重新生成 AGENTS.md 索引

**干什么**：在各宿主目录下写一份 `AGENTS.md`，列出装了哪些 Skill、什么版本、干什么用的，
方便 Agent 自己认。**不动 Skill 本身。**

```bash
skillpm sync
```

`install` / `update` 都会自动生成，一般不用手动跑。手动跑的场景：
手改过 `AGENTS.md` 想恢复，或者装的时候加了 `--no-index`。

> 索引写在一对标记之间，**标记外面你手写的内容会原样保留**。

### 4.10 `skillpm self-update` —— 更新工具本身

```bash
skillpm self-update
```

在哪个目录跑都行。它去 `~/.skillpm-src` 拉最新，然后把这中间的改动打给你看。
和 `skillpm update`（更新 Skill）是两回事，别搞混：

| 命令 | 更新的是 |
|---|---|
| `skillpm update` | **Skill 内容**（怎么拆用例、怎么出报告……） |
| `skillpm self-update` | **skillpm 工具自己**（命令、参数、冲突提示……） |

## 六、冲突怎么处理

**不替你做决定**，和 git 一个思路：报出来、跳过、告诉你怎么解。
**两种冲突，解法完全不一样**，别用错。

### ① 本工具装的，你改过了

```
! code-review 冲突：本地改过，2 个文件和仓库不一致
    SKILL.md
      @@ -92,5 +92,5 @@
      -- **不确定就问，不要猜**：计划放哪些用例、项目、计划名、日期……
      +- **不确定就问，不要猜**（我们组额外要求：日期也要确认）：计划放哪些……
```

红是仓库版、绿是你本地的，`@@` 指出哪一段。两条路：

1. **不要本地改动了** → `skillpm uninstall <Skill名>` 再 `skillpm install`
2. **改动要留** → 自己把改动合进新版，或者干脆把它提到 Skill 仓库去

### ② 目标位置已经有一份，但不是本工具装的

```
! code-review　已存在 2.3.1，不是本工具装的 → 跳过
```

**这种 `uninstall` 卸不掉**（它只管自己装的），别去试。两条路：

1. `skillpm install --force` 让本工具接管——
   **覆盖前会把原来那份完整备份**到 `~/.skillpm/backup/`，包括它不认识的文件
2. 自己把那个目录挪走或删掉，再 `skillpm install`（提示里会给出完整路径）

> 有冲突时命令**返回非零退出码**，CI 里能直接拿来卡。

## 八、常见问题

### "装完敲 skillpm 说 command not found"

**原因**：装的位置不在 PATH 里。

**解决**：

1. 重开一个终端试试——PATH 改动对已开的终端不生效
2. 还不行就重跑一次安装脚本，它会问要不要写进 `.zshrc`/`.bashrc`，回车同意
3. 应急：直接用全路径 `~/.local/bin/skillpm -v`

### "pip install 卡住不动"

**原因**：pip 的构建隔离会去 PyPI 拉 setuptools，网络连不上时要等到超时。

**解决**：**别用 pip**，用 `scripts/install.sh`（默认方式，一个包都不下）。
非要用 pip 就加 `--no-build-isolation`。

### "显示 Successfully installed UNKNOWN-0.0.0"

**原因**：老 pip（<21.3）+ 老 setuptools（<61）读不懂 `pyproject.toml` 里的项目元信息。

**解决**：已经在 1.7.x 加了 `setup.py` 兼容层，新旧两种 setuptools 都验证过。
还遇到的话先 `skillpm self-update`。

### "git clone 那条命令报 destination path already exists"

**原因**：`~/.skillpm-src` 已经在了。

**说明**：这是**正常的**，不影响。命令里用的是 `;` 不是 `&&`，克隆失败后面照样装。
已经装过就直接 `skillpm self-update`，不用再 clone。

### "install 怎么不问我装到哪个 Agent 了"

**原因**：你带了 `--hosts` / `-a` / `-d`，或者在非交互环境（管道、CI）里跑。

**说明**：交互式跑 `skillpm install` **每次都会问**，上次选的默认勾好，回车沿用。

### "提示冲突让我 uninstall，但又说不是本工具装的"

看[第六章](#六冲突怎么处理)的**第 ② 种**：`uninstall` 对它无效，
要么 `install --force` 接管（会先备份），要么自己把目录挪走。

### "我配了两个 Agent，host list 只显示最后配的那个"

**原因**：1.10.0 之前的 `install` 会拿本次选中的宿主**整个覆盖**配置里的宿主表。

**说明**：Skill 其实还好好地装在那个目录里，`skillpm status` 一直能看到——
丢的只是配置表那一行。1.10.0 起 `install` 改成合并保存，并且会从安装记录里
把丢掉的宿主找回来（`host list` 里标黄，下次 `install` 自动并回配置）。
先 `skillpm self-update`，再跑一次 `skillpm host list` 就正常了。

### "--hosts 后面写了 Skill 名，说不认识这个宿主"

**原因**：`--hosts` 会一路吃到下一个选项为止，Skill 名被当成宿主名了。

**解决**：Skill 名写在前面 —— `skillpm install code-review --hosts workbuddy`。

### "更新完想退回旧版"

`~/.skillpm/backup/<Skill名>/<版本>-<时间戳>/` 里有完整的旧版，直接拷回宿主目录即可。

### "同一个 Skill 名在两个仓库里都有，装的是哪个"

装的时候列表里默认是先配的那个；要别的仓库的就点名：`skillpm install 仓库名:Skill名`。
已经装了一个、要换成另一个仓库的，会先问你，默认不换。之后 `update` 只跟着你装的那个仓库走，
永远不会自己换来源。完整规则见「4.6 管理 Skill 仓库」下面的「多个仓库、同名 Skill」。


**发版规矩**：改了版本号（`src/skillpm/__init__.py`）就**必须**在 `CHANGELOG.md`
写一条对应的，`tools/check_release.py` 和 CI 都会检查，对不上不让发。

```bash
uvx --with markdown python tools/manual_html/build.py
```

默认输出到 `docs/使用手册.html`——**它随工具一起发，要提交**：用户敲 `skillpm docs` 打开的就是它，`self-update` 后手册变了会提醒。
改了这几份 md 或 CHANGELOG 没重新生成，`tools/check_release.py` 和测试都会拦下来。

**快速上手里的终端截图**是真实运行录下来的：`tools/manual_html/record_demo.sh` 在一个独立的演示 HOME
（默认 `~/skillpm-demo`，跑完自动删）里从装工具一路跑到卸载，再用 `term2svg.py` 渲染成 `docs/img/qs-*.svg`。
「接入自己的仓库」的截图用 `tools/manual_html/record_onboard.sh` 录：它在本机起一个真的 git 服务（`git_demo_server.py`）当作别的团队的 GitLab，
公开仓库、私有仓库（要令牌）、写错地址都真实跑一遍。
命令输出变了（改了提示文字、排版）就重录一次，再重新生成手册。截图也算在手册的来源指纹里。单文件、不引外网资源，
离线双击就能看；默认打开「快速上手」，顶上切换三份文档，底部是默认折叠的更新日志；左边目录可搜索，代码块一键复制，跟随系统深色模式，手机上也能看。

## 十、几条规矩

- **只碰自己装的东西**：卸载和覆盖都以安装记录为准，别人放的一律不动。
- **覆盖前先备份**：包括 `--force` 覆盖别人的那份，包括对方目录里它不认识的文件。
- **令牌不落日志**：屏幕输出和报错里一律打码。
- **不自动装 Python 包**：只检测、只提示，不动你的 Python 环境。
- **失败要说清楚**：拉不下来会讲明是网络、鉴权还是路径问题，不丢一句"失败了"。
- **没验证过的就标出来**：宿主目录 `likely` 的会让你确认，Windows 脚本没真机跑过也写在文档里。

为了不把无关目录当宿主，有三条限制：
- 只看这两层，不往深找（`~/.codex/vendor_imports/skills` 这类是宿主内置件，不是装 Skill 的地方）；
- `skills` 必须是空的，或者里面至少有一个 `<子目录>/SKILL.md`；
- 跳过 skillpm 自己的 `~/.skillpm*`。

多家共用的目录（比如 `~/.agents/skills`，Cline、Kimi Code CLI、Warp、Zed 都读这里）只列一次，不会装两遍。

Windows 的对应路径是 `%USERPROFILE%\...` 或 `%APPDATA%\...`，表里都带了，会自动选。
